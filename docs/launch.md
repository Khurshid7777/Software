# Ishonch — памятка по предварительному запуску

Порядок: сервер → `.env` → Telegram → запуск → живая проверка → люди и наполнение → открытие для первых пользователей. Галочки — чтобы отмечать по ходу.

Ishonch — связующее звено: деньги через сервис не идут, оплата наличными продавцу или курьеру. Режим `cod_platform` выключен (`COD_PLATFORM_ENABLED=false`) и не включается.

---

## 1. Что подготовить заранее

| Что | Где взять | Зачем |
|---|---|---|
| VPS в Узбекистане: 2 vCPU, 4 ГБ RAM, 40+ ГБ диска, Ubuntu 22.04/24.04 | любой местный хостинг | API, бот, база, фото |
| Домен, например `ishonch.uz` | регистратор | Mini App открывается только по HTTPS |
| Бот | @BotFather | `BOT_TOKEN` |
| Ключ Claude | console.anthropic.com | черновики объявлений, модерация, помощник |
| Распознавание речи с узбекским (по желанию) | любой Whisper-совместимый API | объявления голосом |
| Оферта, политика конфиденциальности, список запрещённых товаров | юрист | ссылки на экране согласия и в профиле |
| Две группы в Telegram: «Модерация» и «Доставка» | создать вручную | карточки на проверку и заказы с кнопками |
| Telegram id администраторов и операторов | @userinfobot | роли |

## 2. Сервер

- [ ] Установить Docker и плагин Compose (`docker compose version`).
- [ ] Склонировать репозиторий в `/opt/ishonch` (ветка `main`).
- [ ] TLS-прокси перед Mini App. Проще всего Caddy — он сам получает сертификат:

  ```
  # /etc/caddy/Caddyfile
  ishonch.uz {
      reverse_proxy 127.0.0.1:8080
  }
  ```

  Mini App (nginx в контейнере `miniapp`) слушает `127.0.0.1:${MINIAPP_PORT:-8080}`. Он отдаёт статику, проксирует `/api` в API и `/tg-webhook` в бота. Порты 3000 и 8081 наружу не открывать.
- [ ] Файрвол: снаружи открыты только 22, 80 и 443.

## 3. `.env`

```bash
cd /opt/ishonch && cp .env.example .env
openssl rand -hex 32   # для INTERNAL_API_TOKEN
openssl rand -hex 16   # для BOT_WEBHOOK_SECRET
openssl rand -hex 24   # для POSTGRES_PASSWORD, MINIO_ROOT_PASSWORD, METRICS_TOKEN (каждому своё)
```

### Обязательно

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `INTERNAL_API_TOKEN` | случайная строка от 32 символов — без неё API не запустится |
| `MINIAPP_URL` | `https://ishonch.uz` |
| `MINIAPP_LINK` | ссылка Mini App из BotFather, например `https://t.me/ishonch_bot/app` |
| `CORS_ORIGIN` | `https://ishonch.uz` (не `*`) |
| `ADMIN_TELEGRAM_IDS` | id администраторов через запятую |
| `OPERATOR_TELEGRAM_IDS` | id операторов доставки |
| `MODERATION_CHAT_ID`, `OPERATOR_CHAT_ID` | id групп (у супергрупп начинаются с `-100`) |
| `ANTHROPIC_API_KEY` | ключ Claude |
| `AI_MONTHLY_LIMIT_USD`, `AI_STRONG_MONTHLY_LIMIT_USD` | потолок расходов в месяц (по умолчанию 50 и 20) |
| `POSTGRES_PASSWORD` | случайный пароль |
| `MINIO_ROOT_PASSWORD` | случайный пароль |
| `STORAGE_DRIVER` | `s3` (compose задаёт сам, но лучше явно) |
| `MINIO_IMAGE`, `MINIO_MC_IMAGE` | конкретный проверенный тег вместо `latest` |
| `BOT_WEBHOOK_URL` | `https://ishonch.uz/tg-webhook` |
| `BOT_WEBHOOK_SECRET` | случайная строка от 16 символов |
| `VITE_OFFER_URL`, `VITE_PRIVACY_URL`, `VITE_PROHIBITED_URL` | ссылки на тексты юриста (вшиваются в сборку Mini App — после изменения нужен `--build`) |

### По желанию

| Переменная | Когда |
|---|---|
| `STT_URL`, `STT_API_KEY` | голосовые объявления; пусто — работают фото и текст |
| `METRICS_TOKEN` | мониторинг Prometheus (`/metrics` с `Authorization: Bearer …`) |
| `REDIS_URL` | только если запускаете больше одной копии API |
| `DIGEST_HOUR` | час утренней сводки админам (по умолчанию 9) |
| `QUIET_HOURS` | `true`: необязательные уведомления не приходят с 22:00 до 8:00 |
| `AI_MODERATION` | `false` — только правила без AI (если ключа пока нет) |
| `IMEI_REGISTRY` | оставить `none`, пока нет доступа к базе краденых IMEI; собственная база «Украли телефон» работает и так |

API при старте пишет в лог `UNSAFE CONFIG`, если пароль базы или MinIO остался по умолчанию или `CORS_ORIGIN=*`.

## 4. Telegram

- [ ] BotFather → `/newbot` → токен в `BOT_TOKEN`.
- [ ] BotFather → `/newapp` (или Bot Settings → Configure Mini App) → URL `https://ishonch.uz`, короткое имя (например `app`) → ссылка `https://t.me/<бот>/app` в `MINIAPP_LINK`.
- [ ] BotFather → Bot Settings → Menu Button → URL Mini App.
- [ ] `/setdescription`, `/setabouttext`, `/setuserpic` — на русском и узбекском.
- [ ] Добавить бота в группы «Модерация» и «Доставка». Назначить его администратором или отключить ему privacy mode, чтобы он видел нажатия кнопок. Записать id групп в `.env`.
- [ ] Для постов в свои каналы продавцы сами добавляют бота админом канала, отдельно настраивать не нужно.

## 5. Запуск

```bash
cd /opt/ishonch
docker compose up -d --build
docker compose ps                 # все сервисы healthy / running
docker compose logs api | tail    # «migrations applied», без UNSAFE CONFIG
curl -s https://ishonch.uz/api/health   # {"ok":true,"db":{"ok":true,...}}
./deploy/smoke.sh                 # проверка после деплоя: все строки ✓, «Всё в порядке»
```

`deploy/smoke.sh` только читает и ничего не меняет. Что он проверяет:
- сайт: TLS-сертификат (действует ещё больше 14 дней), редирект с http, заголовки, сборку Mini App;
- API: `/health`, витрину, закрытый `/api/me`, блок внутреннего токена снаружи, `/metrics`;
- бота: вебхук отклоняет запросы без секрета, токен рабочий, адрес вебхука в Telegram совпадает с `.env`, бот состоит в группах «Модерация» и «Доставка»;
- сервер: контейнеры, `UNSAFE CONFIG` и ошибки в логе за сутки, порты только на 127.0.0.1, свежесть бэкапа и cron, место на диске.

✗ — ошибка (код выхода 1), ! — стоит посмотреть. С ноутбука можно запустить `./deploy/smoke.sh https://ishonch.uz`: серверные проверки тогда пропускаются.

- Миграции (включая 0021–0025) API применяет сам при старте, под блокировкой.
- Справочник категорий и цен (46 моделей) заливается сидом при старте.
- Демо-объявления в боевую базу **не** попадают (они только в тестовом скрипте `dev-seed-catalog`). Не запускайте его на сервере.

### Бэкапы и логи

- [ ] Cron для root:

  ```
  15 3 * * * cd /opt/ishonch && ./deploy/backup.sh >> logs/backup.log 2>&1
  ```

- [ ] Копировать `./backups` на другой диск или к другому провайдеру (rclone, rsync). Бэкап на том же диске не спасёт.
- [ ] Один раз проверить восстановление на тестовой машине (README → «Бэкапы»).
- [ ] Ротация `logs/api.log`: `deploy/logrotate-ishonch` (инструкция внутри файла).
- [ ] Внешний мониторинг доступности: `https://ishonch.uz/api/health` раз в минуту (UptimeRobot, Better Stack и т. п.). Уведомление — в Telegram администратору.

### Обновление

```bash
cd /opt/ishonch && git pull && docker compose up -d --build && sleep 30 && ./deploy/smoke.sh
```

Перед крупным обновлением — внеплановый `./deploy/backup.sh`.

## 6. Живая проверка (до первых пользователей)

Пройти с двух телефонов: один — продавец, другой — покупатель. Третий аккаунт — оператор или администратор.

**Продавец**
- [ ] `/start` в боте → кнопка Mini App открывается, язык переключается RU/UZ.
- [ ] Экран согласия: ссылки на оферту, политику и запрещённые товары открываются.
- [ ] «Продать»: 3 фото и голос (если подключён STT) → вопросы → текст RU и UZ → подсказка цены → публикация → просьба поделиться телефоном → объявление в «Моих объявлениях».
- [ ] Пост в свой канал (бот — админ канала) с кнопкой «Купить».
- [ ] «⋯ Ещё»: поднять, «Предложить избранным», автоснижение, «Предложить магазинам», «Почему не продаётся» со «Спросом».
- [ ] «В отъезде» включить и выключить: объявление пропадает из каталога и возвращается.

**Покупатель**
- [ ] Каталог, поиск: «айфон 13», «ноутбук», «noutbuk», «o'yin». Фильтры, «Класс A–B», «Только проверенные».
- [ ] Карточка: паспорт товара, «Сколько стоит?», похожие, страница продавца, подписка.
- [ ] Сообщение продавцу: доходит через бота, без телефонов и имён; ответ возвращается. «Пожаловаться» и «Заблокировать» под сообщением.
- [ ] Предложение цены → продавец принимает кнопкой в боте → оформление по новой цене.
- [ ] Заказ с доставкой → продавец подтверждает → карточка в группе «Доставка» → оператор: курьер назначен → забрал → доставлено → отзыв. Уведомления приходят всем трём.
- [ ] Спор после доставки → решение администратора.
- [ ] «Встреча лично»: предложить место и время → продавец соглашается → напоминание → «Купил».
- [ ] Сохранённый поиск → «Показать продавцам» → продавец в «Куплю» отправляет подходящее объявление → покупатель получает в бот.
- [ ] «Украли или потеряли телефон» с IMEI, который есть в чужом объявлении: объявление уходит в группу «Модерация».
- [ ] «Скачать мои данные» → файл приходит в бот.

**Администратор**
- [ ] Админка: сводка, модерация (одобрить и отклонить из группы и из Mini App), жалобы, переписка, баны.
- [ ] Импорт цен CSV, тарифы доставки, верификация магазина.
- [ ] Утренняя сводка приходит в `DIGEST_HOUR`.

**Ключи и качество**
- [ ] `pnpm test:ai` на своей машине с настоящим `ANTHROPIC_API_KEY`: черновики, модерация, помощник; посмотреть стоимость запросов.
- [ ] Расходы AI видны в админке («AI»), месячный лимит срабатывает.

Всё, что не сработало, — сразу в список исправлений до открытия.

## 7. Люди и процессы

| Роль | Сколько на старте | Что делает |
|---|---|---|
| Модератор | 1–2, смены 9:00–22:00 | карточки «на проверку», жалобы, переписка, сообщения о краже; цель — ответ до 2 часов |
| Оператор доставки | 1 | вызывает курьера вручную (API курьерских служб нет), меняет статусы кнопками, отвечает на вопросы о доставке |
| Администратор | 1 | баны, споры, цены, тарифы, магазины, утренняя сводка |

- [ ] Договорённость с курьерами (служба или свои люди): цены по районам, приём наличных за товар и передача продавцу в тот же день, фото при заборе (осмотр «Проверено Ishonch»).
- [ ] Внести тарифы в админке («Тарифы»): по районам Ташкента, крупная техника — отдельно.
- [ ] Короткие правила для модераторов: что отклонять (запрещённые товары, контакты в тексте, чужие фото), как решать споры, когда банить.
- [ ] Шаблон ответа «как оплатить»: только наличными при получении или при встрече; никаких предоплат на карту. Это главный сценарий мошенничества.

## 9. Открытие и первые две недели

- [ ] Сначала закрытая группа: 20–50 человек (знакомые продавцы и покупатели). Неделя.
- [ ] Каждый день: утренняя сводка, «Искали, но не нашли» → пополнять словарь написаний (`packages/shared/src/search.ts`) и звать нужные товары.
- [ ] Модерация: доля отклонённых AI, ложные дубли по фото — при необходимости подстроить пороги.
- [ ] Ошибки: `docker compose logs api | grep -i error`, внешний мониторинг, `/metrics` (если включён).
- [ ] Расходы AI против лимита; при росте — уменьшить `ASSISTANT_PER_DAY` или `CHECKS_PER_DAY` в админке.
- [ ] Обратная связь от первых продавцов: что непонятно, где бросают публикацию (воронки в сводке).

Метрики успеха — `docs/plan.md`, раздел «Как поймём, что работает».
